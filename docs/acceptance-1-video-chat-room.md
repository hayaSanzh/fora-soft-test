## 2. Решения, принятые при реализации

| Решение | Почему |
|---|---|
| Весь монорепо — **ESM** (`"type": "module"`), серверные относительные импорты с расширением `.js` | Один модульный формат вместо dual-build: клиент собирается Vite, `shared` линкуется как обычный npm-пакет, сервер запускается `node dist/index.js` без транспиляции в CJS |
| `shared` собирается в `dist` и подключается как пакет, а `pretest`/`pretypecheck`/`predev` собирают его автоматически | Компиляция сервера через `tsc` не умеет захватывать исходники за пределами `rootDir`; при этом ручная пересборка забывается — хуки убирают этот класс ошибок |
| Скрипт `prepare` в `shared` удалён | `npm ci --ignore-scripts` в Docker всё равно вызывал его для воркспейса и падал (`tsc` ещё не установлен). Сборка теперь явная: в хуках и в `Dockerfile` |
| Отдельные `tsconfig.build.json` у `shared` и `server` | Иначе `*.test.js` попадают в `dist` и в прод-образ; при этом типы тестов по-прежнему проверяются основным `tsconfig.json` |
| Тесты используют исходники `shared` (алиас vitest) | Покрытие по `shared/` иначе всегда нулевое, а прогон требовал бы предварительной сборки |
| Порт контейнера публикуется как `127.0.0.1:3001:3001` | См. §4 — за NAT docker проверка «/health только внутри сети» иначе не значит ничего |
| Добавлен флаг `TRUST_PROXY` (дефолт `loopback`) | Реальный адрес клиента берётся из `X-Forwarded-For` только от доверенного прокси; иначе заголовок можно подделать |
| HTTPS в dev включается наличием `client/certs/{key,cert}.pem`, без плагина | TDD §12.1 требует именно mkcert. Плагин-обёртка тянет загрузку бинарника в момент запуска dev-сервера; чтение готовых сертификатов проще и работает офлайн. Без сертификатов — http на `localhost`, что остаётся secure context |
| Сверх плана добавлено ESLint-правило против `removeTrack` | TDD R4 предлагает закрепить это код-ревью; правило надёжнее чеклиста и объясняет альтернативу прямо в сообщении об ошибке |
| `helmet` и CSP **не** добавлены | По плану это задача 4.8 |
| `/health` возвращает `rooms: 0` | Счётчик комнат появится вместе с `RoomStore` (задача 3.1); шов `getStats()` уже есть и покрыт тестами. `participants` уже реальный — число подключённых сокетов |

## 4. Найдено и исправлено в процессе

1. **`/health` был доступен снаружи в контейнере.** Первый прогон `docker compose up` показал `200` на `http://127.0.0.1:3001/health` с хоста — и это лишь верхушка проблемы: за NAT docker адрес источника подменяется адресом шлюза из приватного диапазона, поэтому проверка «внутри сети» пропустила бы **любого** клиента, если порт опубликован на `0.0.0.0`. Исправлено тремя изменениями: публикация только на `127.0.0.1`, настраиваемый `TRUST_PROXY`, явный комментарий-предупреждение в коде. В прод доступ к `/health` дополнительно закрывается на nginx (задача 15.2).
2. **Тесты попадали в прод-сборку** (`server/dist/config.test.js`) — добавлены `tsconfig.build.json`.
3. **`npm ci --ignore-scripts` в Docker падал** на `prepare`-скрипте воркспейса `shared` — скрипт удалён, сборка сделана явной.
4. **Типизированные ESLint-правила ругались на собственные конфиги** (`eslint.config.js`, `vitest.config.ts` не входят ни в один tsconfig) — для них type-checked правила отключены.
5. **`vi.stubEnv` не влияет на `import.meta.env`** в vitest 3 — вместо обхода конфигурации переведены на чистые фабрики от окружения.
6. **Значение `HEALTH_ALLOWLIST` из группы 0 было ошибочным**: префикс `172.16.` покрывал только одну /16 из приватной /12, то есть сети docker (`172.17.x`) считались бы внешними. Приватные диапазоны теперь распознаются функцией `isInternalAddress`, а `HEALTH_ALLOWLIST` служит для дополнительных адресов и по умолчанию пуст.
