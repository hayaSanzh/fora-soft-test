## 2. Решения при реализации

| Решение | Почему |
|---|---|
| Сверх плана детектор различает **отсутствие HTTPS** (`INSECURE_CONTEXT`), и эта проверка идёт **первой** | На `http://192.168.x.x` браузер вообще не отдаёт `navigator.mediaDevices`, поэтому проверка API сработала бы раньше и дала неверный текст про «неподдерживаемый браузер» (§4.1, дефект 3). Это самая частая ошибка LAN-проверки (TDD §12.1) |
| Имя передаётся на `/:roomId` **через переменную в памяти модуля** (`lib/pendingJoin.ts`) | В URL имя попадать не должно (ссылкой делятся), web storage запрещён PRD §5, а состояние навигации react-router переживает перезагрузку и нарушает ФТ-28 (см. §4.1, дефект 2) |
| Один `JoinScreen` на оба сценария, режим через prop | Логика идентична, различаются подпись кнопки и подзаголовок. Два компонента разъехались бы при первой же правке валидации |
| Подсказка про **обязательность** имени — по `blur` или попытке отправки; про **недопустимые символы и длину** — сразу при вводе | Пустое поле в начале не должно упрекать пользователя. Но кнопка при невалидном имени `disabled`, поэтому объяснение обязано появляться до отправки: иначе Enter ничего не делает и причина непонятна (§4.1, дефект 1) |
| Счётчик считает **очищенную** длину | Иначе он показывает символы, которые всё равно будут вырезаны (пробелы, zero-width) |
| `maxLength` на поле **плюс** валидация | Атрибут не мешает вставке из буфера в части браузеров, поэтому заменять им проверку нельзя |
| Мусорный `roomId` в URL → экран «Некорректная ссылка» с кнопкой создания | ФТ-5 говорит, что «комнаты не найдено» не существует, но `roomId`, не проходящий формат, — это не комната, а битая ссылка (TDD §8.1) |
| Reducer возвращает **то же** состояние на недопустимый переход | Бросать исключение в reducer нельзя: React вызывает его при повторном рендере в StrictMode |
| Дубли `chat:message` по `id` отбрасываются | Сервер рассылает сообщение всем включая автора; повторная доставка не должна дублировать строку |
| Тесты рендера через `react-dom/server`, а не jsdom | jsdom + RTL — задача 12. Но проверить, что экраны вообще рендерятся и содержат нужные строки, нужно уже сейчас: `renderToStaticMarkup` даёт это без новых зависимостей |
| `styles.css` минимальный | PRD §6: «работает и понятно», приоритет читаемости. Сетка, плитки и адаптив от 1024px — группа 10 |

## 4. Найдено и исправлено

### 4.1 Дефекты, найденные ручной приёмкой в браузере

Три дефекта, которые автоматические тесты пропустили, — все три показательны.

**1. Подсказка не появлялась по Enter при недопустимом имени (задача 5.4).**
Кнопка отправки `disabled`, пока имя невалидно. Из этого следует, что нажатие Enter **не порождает событие `submit`**, обработчик не выполняется, `touched` не выставляется — и подсказки нет. Получался тупик: мёртвая кнопка без объяснения причины.
*Исправление:* подсказка показывается сразу, как только в поле появилось непустое недопустимое значение, плюс по `blur` для пустого поля. Условие вынесено в чистую функцию `shouldShowNameHint()` и покрыто 4 тестами; интерактивная проверка (реальный ввод) добавится в задаче 12.1.
*Вывод для последующих групп:* если кнопка `disabled`, путь показать ошибку должен существовать **до** попытки отправки.

**2. Перезагрузка страницы комнаты не спрашивала имя заново (ФТ-28).**
Имя передавалось через `location.state` react-router. Ошибочное предположение: состояние навигации **сериализуется в запись истории браузера и переживает F5**, поэтому после перезагрузки `RoomPage` снова видел имя и сразу уходил в `acquiringMedia`. Требование ФТ-28 («перезагрузка = новый вход с повторным вводом имени») не выполнялось.
*Исправление:* новый модуль `lib/pendingJoin.ts` — обычная переменная в памяти модуля. Она живёт ровно до перезагрузки: `sessionStorage` запрещён PRD §5 (и ESLint-стражем), а состояние навигации, как выяснилось, слишком долговечно. Чтение сделано идемпотентным: в StrictMode инициализатор `useReducer` вызывается дважды, и семантика «прочитал — стёр» потеряла бы имя. 7 тестов, включая проверку, что имя не подхватывается для другой комнаты.

**3. На LAN-адресе без HTTPS показывалось не то сообщение (ФТ-36).**
Порядок проверок в `detectWebRtcSupport` был «сначала API, потом secure context». Но на небезопасном origin Chrome **вообще не создаёт `navigator.mediaDevices`**, поэтому первым срабатывал признак «нет getUserMedia» и пользователь получал «браузер не поддерживает WebRTC» — сообщение неверное по сути: браузер поддерживает, дело в схеме URL.
*Исправление:* secure context проверяется первым. Добавлен регрессионный тест на форму окружения, которую реально отдаёт Chrome на insecure origin (`RTCPeerConnection` есть, `navigator.mediaDevices` отсутствует, `isSecureContext: false`).

### 4.2 Найдено при разработке

1. **Тест `formatTime` зависел от часового пояса машины.** Сравнивал результат с `UTC` и `Asia/Tokyo`, а машина в UTC+5 → падение. Переписан: сравнение идёт с поясом самого окружения, а факт пересчёта проверяется отдельным утверждением. Проверено прогоном в `TZ=UTC` и `TZ=Asia/Tokyo`.
2. **Проверка бандла ожидала строки, которых там быть не должно.** «Комната заполнена» и «покинул комнату» ещё не используются кодом, и Rollup их выбрасывает. Это желаемое поведение; проверка исправлена, а факт tree-shaking строк зафиксирован как свойство.
3. Два замечания линтера (неиспользуемая переменная в тесте, лишнее приведение типа `window`) — исправлены.

## 6. Что нужно проверить руками (повторно после исправлений)

Автоматика не проверяет **интерактивность** (это задача 12) и **реальный браузер**. Одна ручная проверка на 3 минуты:

```bash
npm run build
NODE_ENV=production PORT=3001 STATIC_DIR=./client/dist node server/dist/index.js
# откройте http://localhost:3001
```

1. **Стартовый экран.** Видно поле «Ваше имя», подсказку про допустимые символы, счётчик `0 / 30`, кнопка «Создать комнату» **серая и неактивная**.
2. **Валидация (исправлено, дефект 1).** Введите `<script>` — кнопка остаётся неактивной **и сразу появляется красная подсказка** про допустимые символы (ждать Enter больше не нужно). Введите `Анна-Мария` — подсказка исчезает, кнопка активна, счётчик `11 / 30`. Отдельно: очистите поле и щёлкните мимо — появится подсказка «Введите имя…».
3. **Создание комнаты.** Нажмите «Создать комнату» → адрес меняется на `/<12 символов>`, экран показывает «Запрашиваем доступ к камере и микрофону…» и ваше имя. Второго запроса имени быть не должно.
4. **Перезагрузка (ФТ-28, исправлено, дефект 2).** Нажмите F5 на странице комнаты → имя спрашивается снова, кнопка называется «Войти», а не «Создать комнату».
5. **Битая ссылка.** Откройте `http://localhost:3001/ab` → «Некорректная ссылка» и кнопка создания комнаты, а не белый экран.
6. **Отсутствие HTTPS (ФТ-36, исправлено, дефект 3).** Узнайте адрес: `hostname -I | awk '{print $1}'`. Откройте `http://<этот-адрес>:3001/` **с другого устройства в той же сети или в том же браузере** → полноэкранное сообщение **про HTTPS** (не про неподдерживаемый браузер). Важно: по `localhost` и `127.0.0.1` это сообщение не появится — они считаются secure context by exception, и это правильно.

Проверок, требующих железа (камера, микрофон), в группе 5 нет — они появятся с группой 7.
