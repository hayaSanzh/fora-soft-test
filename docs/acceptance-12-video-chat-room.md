## 2. Решения при реализации

**Два project'а vitest, а не одно окружение.** TDD §11.1 обещал отдельный project с jsdom — сделано именно так: `node` (сервер, общий пакет, чистая логика, разметка через `react-dom/server`) и `dom` (jsdom + RTL). Признак проекта — суффикс `.dom.test.tsx`, а не отдельный каталог: тесты лежат рядом с компонентами, как и все остальные. Побочный выигрыш — прогон ускорился: project'ы исполняются параллельно (3,9 с против 18 с).

**Матчеры `jest-dom` подключены ради диагностики, а не краткости.** `expect(button).toBeDisabled()` при падении печатает состояние элемента; `expect(button.disabled).toBe(true)` — только «false вместо true».

**Привязка потоков вынесена из хука** в `services/videoAttachments.ts`. В приёмке группы 11 она была записана как ограничение: «требует рендера, покрывается в группе 12». Вместо того чтобы тащить сессию в jsdom, логика вынесена туда, где ей и место — рядом с `localMedia`, `PeerManager` и `roomConnection`, которые тоже не знают про React. Теперь три её нюанса проверяются без jsdom вовсе.

**Что проверяется только в DOM и нигде больше:**

| Свойство | Почему разметки недостаточно |
|---|---|
| Подсказка при недопустимом имени появляется во время набора | требует ввода символ за символом |
| `<video>` остаётся **тем же узлом** при переключении камеры | требует ре-рендера и сравнения ссылок на узлы |
| Автопрокрутка не срабатывает, когда пользователь листает историю | требует событий прокрутки и метрик контейнера |
| Подтверждение копирования ссылки | появляется только после разрешения промиса Clipboard API |
| Кнопка «Повторить вход» двигает машину состояний | требует связки экрана с reducer'ом и настоящего клика |

## 4. Найдено и исправлено

1. **★ Мой тест утверждал неверный контракт санитизации.** Я проверял, что чат сворачивает внутренние пробелы (`'привет   всем'` → `'привет всем'`) — но это поведение **имени**, а не сообщения: `sanitizeName` сворачивает пробелы, `sanitizeText` только срезает крайние. И это правильно: выравнивание текста пробелами пользователь делает осознанно. Тест исправлен на фактический контракт, а различие двух функций теперь зафиксировано в нём явно.
2. **★ Тест зависел от окружения.** В тесте `App` я сначала утверждал, что после отказа камеры появится экран «Нет связи с сервером». Это правда — но только если сервер разработки **не** запущен: сокет идёт на реальный адрес, и при живом сервере клиент вошёл бы в комнату. Тест переписан так, чтобы про исход подключения ничего не утверждать. Проверено прогоном с поднятым сервером на 3001: 7/7 проходят в обоих случаях.
3. **Две гонки в моих же тестах.** Утверждения про промежуточные экраны (`acquiringMedia`, `connecting`) не выдерживали скорости машины: отказ камеры приходит мгновенно, и состояние успевает уйти дальше. Заменены на проверки наблюдаемого результата (URL изменился, экрана ввода имени больше нет).
4. **★ `verify` не проверял форматирование.** Prettier нашёл расхождения в 8 файлах, накопившиеся за группы 10–12 — ровно потому, что `npm run verify` вызывал typecheck, lint, test и build, но не `format:check`. Формат исправлен, а проверка добавлена в `verify`: иначе расхождение вернулось бы к следующей группе. Это тот же класс дефекта, что и «`verify` не собирал клиент» из группы 7 — проверка, которая не входит в единую команду, не выполняется никогда.
5. **ESLint поймал `unbound-method`** на `navigator.mediaDevices.getUserMedia as ReturnType<typeof vi.fn>`: чтение метода отдельно от объекта. Мок теперь сохраняется при создании заглушки, а не вытаскивается из `navigator`.

## 6. Что нужно проверить руками

Группа 12 не меняет поведение приложения — только тесты, вынос `videoAttachments` и удаление мёртвого кода. Поэтому ручные проверки короткие: убедиться, что рефакторинг ничего не сломал.

```bash
npm run serve
# http://localhost:3001 — обязательно localhost
```

1. **★ Видео пира появляется** (проверка выноса `videoAttachments`). Две вкладки → в каждой видно и себя, и собеседника. Это главный риск группы: привязка потоков к элементам переписана.
2. **★ Звук пира слышен.** Скажите что-нибудь в одной вкладке (или включите музыку) → слышно в другой. Проверяет, что `play()` по-прежнему вызывается.
3. **★ Переключение камеры не ломает звук** (риск R5). Выключите камеру → у собеседника заглушка, **но звук продолжает идти**.
4. **Уход участника.** Закройте вкладку → плитка исчезает, у остальных нет чёрного прямоугольника.
5. **Третий участник.** Войдите третьей вкладкой → все видят всех, раскладка 2×2.
6. Регрессии групп 10–11: плитки не растут, заглушка в своей плитке, всё в окне без прокрутки, чат и копирование ссылки работают.
