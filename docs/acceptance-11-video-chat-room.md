## 2. Решения при реализации

**Исчерпывающий `switch` вместо `default`.** Раньше `RoomPage` заканчивался ветвью `default`, которая показывала «Подключаемся…» — то есть любое состояние, для которого забыли экран, молча выглядело бы как подключение. Теперь разобраны все девять состояний машины §3.3, а `default` убран: новое состояние **не скомпилируется**, пока для него не добавлен экран. Требование «никогда не белый экран» стало проверяемым компилятором, а не намерением.

**Экран несовместимости — единственный без кнопки.** Выйти из этого состояния внутри приложения нельзя: нужен другой браузер или HTTPS. Кнопка «Повторить» здесь была бы ложью, и это закреплено тестом (`не содержит <button>`).

**Баннер устройств — в потоке страницы, а не оверлеем.** Ошибка медиа не терминальна (TDD §8.3): пользователь остаётся в звонке, видит и слышит остальных, пишет в чат. Перекрывать ему видео сообщением об отказе камеры неправильно. Кнопка «Скрыть» задействовала действие `MEDIA_ERROR_DISMISSED`, объявленное в reducer'е ещё в группе 5 и до сих пор ни разу не отправлявшееся.

**Баннер показывается и на экране ожидания.** `MEDIA_FAILED` переводит машину из `acquiringMedia` в `connecting`; если вход задержится, пользователь должен уже видеть, что доступа к камере нет (ФТ-33), а не узнать об этом после попадания в комнату.

**`undefined` состояние соединения = «Соединение…», а не «всё хорошо».** Состояние приходит из `onconnectionstatechange`, до первого события его нет. Трактуя `undefined` как норму, в самый заметный момент — сразу после входа участника — плитка была бы чёрной без единого объяснения.

### 2.1 Автозапуск (11.5) — три правила

| Правило | Что было бы при нарушении |
|---|---|
| Блокировкой считается **только** `NotAllowedError` | `play()` отклоняется и штатно, чаще всего `AbortError` (предыдущий вызов прерван новым `srcObject`; в StrictMode это происходит регулярно). Считая блокировкой любую ошибку, оверлей «Включить звук» выскакивал бы при работающем звуке |
| `play()` вызывается для всех элементов **синхронно**, до первого `await` | разрешение действует на время обработки жеста; `await` в цикле теряет его — со второго элемента звука не будет |
| Заглушать элемент ради автозапуска **запрещено** | `muted = true` разрешает воспроизведение всегда — ценой «видно, но не слышно» (ФТ-19), молча и без ошибок в консоли. Заглушён только self-view, и только против эха |

Логика вынесена в чистый `lib/autoplay.ts`: её нужно проверять без jsdom, а ломается она незаметно.

### 3.3 Ключевой тест — контрпример на наивную реализацию

В `autoplay.test.ts` есть тест, который **воспроизводит ошибку** отвергнутой реализации: модель браузера разрешает `play()` только пока «жест активен» (окно закрывается в конце текущей микрозадачи). При последовательном `await tryPlay(...)` в цикле результат `[false, true, true]` — первый элемент успел, остальные заблокированы. Реализация с предварительным созданием всех промисов даёт `[false, false, false]`. Без такого теста разница между двумя вариантами кода незаметна: оба «работают» на одном участнике.

### 3.4 Проверки на собранном бандле и живом сервере

- все девять новых русских строк присутствуют в собранном JS;
- все восемь новых CSS-классов присутствуют в собранном CSS;

## 4. Найдено и исправлено

1. **★ Оверлей «Включить звук» блокировал элементы управления.** Первая версия помещала `.gate` с `inset: 0` внутрь `.room__stage`, а там лежат не только плитки, но и кнопки. Оверлей перехватывает клики — то есть подсказка про звук **запирала бы пользователя в комнате**: ни выйти, ни выключить микрофон. Исправлено обёрткой `.stage__video` вокруг одной сетки. Закреплено тремя стражами: `.gate` растянут по рамке, рамка — обёртка сетки (а `.room__stage` не позиционирован), и в разметке `<Controls>` лежит **вне** обёртки с оверлеем. Страж проверен пробой: возврат `position: relative` на `.room__stage` роняет тест.
2. **Формулировка «соединение потеряно» просачивалась в текст про сервер.** ФТ-31 запрещает этот оборот применительно к участникам (сервер не отличает закрытие вкладки от обрыва канала). В тексте про сервер он формально допустим, но такие формулировки расползаются по интерфейсу при копировании, поэтому добавлен тест, запрещающий его целиком.

## 6. Что нужно проверить руками

```bash
npm run serve
# http://localhost:3001 — обязательно localhost
```

1. **★ Комната заполнена (ФТ-8, US-5).** Откройте пять вкладок одной комнаты. Пятая → «Комната заполнена». Закройте одну из первых четырёх и нажмите **«Повторить вход»** → должны попасть в комнату, **не вводя имя заново**. Нажмите «Повторить вход», когда мест по-прежнему нет → снова экран «Комната заполнена», без белого экрана.
2. **★ Нет связи с сервером (ФТ-35, US-13).** Находясь в комнате, остановите сервер (`Ctrl+C` в терминале) → экран «Нет связи с сервером». Запустите сервер снова, нажмите **«Повторить»** → снова в комнате.
3. **★ Отказ в доступе к камере (ФТ-33, US-12).** В адресной строке нажмите значок камеры → «Блокировать» → перезагрузите страницу и войдите. Ожидается: **вы в комнате**, баннер «Нет доступа к камере или микрофону… Вы в комнате, но вас не видно и не слышно», чат работает, собеседника видно и слышно. Нажмите «Скрыть» → баннер исчезает и сам не возвращается.
4. **Баннер на экране ожидания.** Заблокируйте камеру и войдите в комнату при остановленном сервере: пока идёт «Подключаемся…», баннер об отказе камеры уже виден.
5. **★ Оверлей «Включить звук» (ФТ-37).** Настройки сайта → «Звук» → **«Блокировать»** (в Chrome: значок слева от адреса → «Настройки сайта» → «Звук»). Войдите двумя вкладками. Ожидается: поверх сетки — «Браузер заблокировал автоматическое воспроизведение звука», кнопка «Включить звук»; **кнопки «Выйти» и тумблеры при этом доступны** (это был дефект, см. §4.1); один клик по «Включить звук» → оверлей исчезает и звук появляется. Не забудьте вернуть настройку.
6. **Индикация соединения (ФТ-34).** При входе нового участника на его плитке кратко видно плашку «Соединение…», которая исчезает при появлении картинки. Красная плашка «Нет соединения с участником» **на одной машине не воспроизводится**: для неё нужны две сети с симметричным NAT и отсутствие TURN (риск R1). Отключение сети в DevTools здесь не подходит — оно рвёт и сокет, поэтому участник просто исчезнет из списка (`peer:left`), а не останется с красной плашкой. Этот путь закрыт автотестами (6 тестов на плашку + мок соединения в `PeerManager.test.ts`) и войдёт в E2E-проверки группы 13.
7. **★ Страница без HTTPS (ФТ-36).** Откройте `http://$(hostname -I | awk '{print $1}'):3001/` с другого устройства или в другом окне → «Ваш браузер не поддерживает WebRTC» с текстом про HTTPS. На `localhost` этого сообщения быть не должно.
8. **Битая ссылка.** Откройте `http://localhost:3001/ab` → «Некорректная ссылка» и кнопка «Создать комнату», ведущая на главную. (`ab` короче минимума в 4 символа по `ROOM_ID_PATTERN`; ссылка вида `/abcd` — уже валидная комната, состояния «комната не найдена» не существует по ФТ-5.)
9. **Выход (ФТ-27).** «Выйти» → «Вы вышли из комнаты» + «Вернуться» → снова спрашивают имя (ФТ-28).
10. **Проверка на отсутствие регрессий группы 10.** Плитки не растут со временем; при выключенной камере заглушка занимает только свою плитку; заголовок и кнопки видны без прокрутки страницы.
