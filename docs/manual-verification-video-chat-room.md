## 0. Как пользоваться

Каждый пункт — отдельная проверка с ожидаемым результатом. Отметка `[ ]` → `[x]` ставится **только** после фактического выполнения на железе; автоматика эти пункты не закрывает и закрыть не может.

Перед началом:

```bash
npm run verify        # typecheck, lint, формат, 623 теста, сборка
npm run test:e2e      # 40 E2E: Chromium + Firefox, настоящий WebRTC
npm run serve         # http://localhost:3001
```

Если `verify` или `test:e2e` не проходят — ручные проверки бессмысленны, сначала разбираем автоматику.

Эти пункты TDD §11.5 **перестали быть ручными** по ходу групп 13–14, и повторять их руками не нужно:

## 1. Аппаратный индикатор камеры (ФТ-19, US-7) — 14.2

**Почему вручную:** состояние светодиода недоступно из браузера ни одним API.

- [ ] Chrome: войти в комнату → **индикатор камеры на корпусе горит**.
- [ ] Нажать «Выключить камеру» → **индикатор гаснет в течение ~1 с**.
- [ ] Нажать «Включить камеру» → индикатор загорается снова, у собеседника появляется картинка.
- [ ] Повторить в Firefox.
- [ ] Повторить в Edge.

**Почему это важно:** если индикатор продолжает гореть при «выключенной» камере, значит дорожка не остановлена, а только заглушена — пользователь считает, что его не видно, а его видно. Это нарушение ФТ-19 и приватности. В коде за это отвечает остановка видеодорожки (`track.stop()` + `replaceTrack(null)`), а не `enabled = false` — микрофон, наоборот, гасится через `enabled`, поэтому у него индикатор может оставаться активным, и это ожидаемо.

- [ ] Проверить обратное для микрофона: «Выключить микрофон» → собеседник не слышит, при этом индикатор микрофона может остаться активным. Это **не дефект** (TDD §4.4: остановленную аудиодорожку пришлось бы запрашивать заново и ренегоциировать).

## 2. LAN-прогон между физическими машинами (PRD §7, US-6) — 14.3

**Почему вручную:** fake-media на loopback не отражает реальный путь: нет сети, нет разных кодеков, нет NAT.

Подготовка (HTTPS обязателен: без него `getUserMedia` недоступен вне `localhost`):

```bash
# на машине-сервере
mkcert -install
mkcert 192.168.1.10        # ваш LAN-IP
# сервер за nginx с этим сертификатом (docs: TDD §12.1) либо любой TLS-прокси
```

- [ ] 2 машины: звонок устанавливается, видео и звук в обе стороны.
- [ ] 3–4 машины: все видят всех, раскладка 2×2.
- [ ] Замерить задержку: открыть `chrome://webrtc-internals` → выбрать соединение → график `currentRoundTripTime`. **Ожидается ≤ 500 мс** (PRD §7). Записать фактические значения.
- [ ] Альтернативный замер из консоли страницы:

```js
// в DevTools любой вкладки комнаты
const pcs = [];  // если нужно — перехватить как в e2e/helpers.ts
// либо прямо в webrtc-internals: candidate-pair → currentRoundTripTime
```

- [ ] Субъективно: речь не рассинхронизирована с картинкой, задержка не мешает разговору.

**Фактические значения (заполнить):** RTT ___ мс, jitter buffer ___ мс, число участников ___.

## 3. Физическое отключение USB-камеры (ФТ-20, US-7) — 14.4

**Почему вручную:** требует железа; программно `track.onended` не вызвать так, как это делает драйвер.

- [ ] Войти в комнату с USB-камерой, дождаться картинки у собеседника.
- [ ] **Выдернуть камеру из порта.**
- [ ] Ожидается: тумблер камеры переходит в «Включить камеру», у собеседника появляется заглушка-силуэт, баннер «Устройство отключено. Включите его снова, когда оно появится».
- [ ] **Звонок не разрывается:** звук продолжает идти, чат работает, остальные участники на месте.
- [ ] Вставить камеру обратно → нажать «Включить камеру» → картинка возвращается.
- [ ] Проверить, что баннер не мешает: его можно закрыть кнопкой «Скрыть».

## 4. Отсутствие эха при живых микрофонах (риск R9) — 14.6

**Почему вручную:** субъективная оценка; автоматика не слышит.

- [ ] 4 участника **на разных машинах в одном помещении**, все микрофоны включены, **без наушников**.
- [ ] Ожидается: слышен свист/эхо — это нормальное физическое явление, а не дефект приложения.
- [ ] Раздать наушники → эхо исчезает.
- [ ] **Ключевая проверка:** участник **не слышит собственный голос** ни при каком сочетании (это и есть проверка `muted` на своей плитке — ФТ-18). Если слышит себя — дефект.
- [ ] Проверить, что выключение микрофона одним участником убирает его вклад в эхо у остальных.

## 5. Кросс-браузер: Edge (PRD §7) — 14.6

**Почему вручную:** Playwright не поддерживает Edge с фейковыми устройствами так, как Chromium и Firefox. Firefox автоматизирован (`e2e/cross-browser.spec.ts`).

- [ ] Edge 100+: вход, звонок вдвоём с Chrome, видео и звук в обе стороны.
- [ ] Выключение камеры → заглушка у собеседника, **звук продолжает идти**.
- [ ] Чат: сообщение с именем и `HH:MM` доходит в обе стороны.
- [ ] Выход → устройства освобождены (индикатор камеры погас).

**Что искать особо:** Edge на движке Chromium, поэтому различия ожидаются минимальные. Наибольший риск — политика автозапуска: если удалённое аудио не стартует, должен появиться оверлей «Включить звук» (ФТ-37).

## 6. Загрузка CPU при 4 участниках (риск R2) — 14.7

**Почему вручную:** нагрузка зависит от машины; Playwright не измеряет CPU достоверно.

- [ ] 4 участника (можно 4 вкладки на одной машине, но лучше 4 машины).
- [ ] Открыть системный монитор / `chrome://system` → записать загрузку CPU процесса рендерера.
- [ ] Записать фактические значения: CPU ___ %, разрешение видео ___, fps ___.
- [ ] Если картинка сыпется или упирается в канал — включить потолок битрейта и перепроверить:

```bash
VITE_MAX_VIDEO_BITRATE=800000 npm run build && npm start
```

- [ ] Ожидается: битрейт исходящего видео ограничен (виден в `chrome://webrtc-internals` → `outbound-rtp` → `targetBitrate`), качество ниже, но картинка стабильная.

**Флаг проверен автотестом** (`PeerManager.test.ts`, «включённый потолок битрейта»): `maxBitrate` попадает в каждый encoding видеоотправителя и не касается аудио. То есть механизм работает — ручная часть только в выборе значения по факту замеров.

## 7. Прочие проверки из состава требований

- [ ] **ФТ-28, перезагрузка:** F5 в комнате → имя спрашивают заново, история чата пуста.
- [ ] **ФТ-36, без HTTPS:** открыть `http://<LAN-IP>:3001/` → сообщение про HTTPS, а не белый экран.
- [ ] **ФТ-37, автозапуск:** настройки сайта → «Звук» → «Блокировать» → войти → оверлей «Включить звук», клик по нему возвращает звук, кнопки «Выйти» и тумблеры при этом доступны.
- [ ] **ФТ-33, частичный отказ:** заблокировать только камеру → «Нет доступа к камере. Вы в комнате, вас слышно, но не видно».
- [ ] **Q10, завершение работы сервера:** `Ctrl+C` на сервере → участники получают системное сообщение «Сервер завершает работу», затем экран «Нет связи с сервером»; сервер завершается за ~2–3 с.
