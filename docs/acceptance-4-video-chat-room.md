## 2. Решения при реализации

| Решение | Почему |
|---|---|
| Мусорное `media` в `room:join` **не отклоняет вход**, а трактуется как «оба устройства выключены» | В контракте `JoinError` нет кода для некорректного `MediaState`, а ФТ-14 прямо разрешает вход без устройств. Отказ был бы строже требования |
| Системное сообщение о входе добавляется **после** снятия снапшота и рассылается всем, включая вошедшего | Иначе вошедший получил бы его дважды: в истории снапшота и событием. Проверено тестом «ровно один раз» |
| ack отправляется **до** broadcast'ов | Клиент успевает подготовить состояние комнаты до первых событий (`peer:joined`, `chat:message`) |
| `delete socket.data.roomId` в самом начале `handleLeave` | Гонка `room:leave` + `disconnect` (и просто двойной `room:leave`) не должна давать двойную рассылку `peer:left` |
| Лимитеры создаются в замыкании на соединение, а не в `Map` по `socket.id` | Нет отдельного пути очистки → нет утечки при обрыве |
| Скользящее окно для сигналинга, а не фиксированное | С фиксированным окном клиент отправляет 2 × limit событий на стыке двух окон и остаётся незамеченным. Проверено отдельным тестом |
| Флуд чата отвечает `RATE_LIMITED` и **не рвёт** сокет; флуд сигналингом **рвёт** | Быстро печатающий человек — не атака. 100 `signal:*` за 10 с человеком быть не может (TDD §10.4) |
| Сигналинг чужому адресату отбрасывается **молча** | Ответ «такого участника нет» подтверждал бы существование чужих `socket.id` |
| `'unsafe-inline'` в CSP допущено только для `style-src` | React ставит инлайновые style-атрибуты; для скриптов не допущено ни `unsafe-inline`, ни `unsafe-eval` — проверяется тестом |
| Стенд для integration-тестов без моков | Проверяется контракт целиком: broadcast'ы, порядок событий, ack. Мок socket.io проверял бы только вызовы |
| Express-CORS не добавлялся | Клиент и сервер на одном origin; CORS настроен там, где он нужен — в socket.io (задача 1.4, TDD §10.4) |

## 4. Найдено и исправлено в процессе

1. **Тест «порядок 50 сообщений» падал, получая только 5** — сработал антифлуд с дефолтным `burst 5`. Это корректное поведение: 50 сообщений подряд не отправит и живой человек. Тест теперь явно поднимает лимит и объясняет, почему.
2. **Два теста presence были гоночными**: подписка на `chat:message` после `await join()` ловила системное сообщение о **входе** вместо ожидаемого о выходе. Добавлен помощник `waitForMatch(client, event, predicate)`; тесты стали детерминированными.
3. **Тест «неизвестный roomId создаёт комнату» использовал кириллический id** — он не проходит формат `^[A-Za-z0-9_-]{4,64}$`. Тест исправлен и дополнен проверкой, что кириллица действительно отклоняется.
4. **Ошибка в сквозном пробнике**: проверка `/health` после выхода одного участника ожидала 3, тогда как во второй комнате оставался ещё один участник (3 + 1 = 4). Сервер был прав, пробник — нет. Счётчики перепроверены отдельным прогоном: 2/3 → 2/2 → 1/1 → 0/0, всё верно.
