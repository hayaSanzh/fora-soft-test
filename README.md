# Видеочат-комната

Веб-приложение для видеозвонка до четырёх участников с текстовым чатом. Комната создаётся одним нажатием, приглашение — ссылка. Медиа идёт **напрямую между браузерами** (WebRTC mesh), сервер выполняет только сигналинг и раздаёт статику.

Тестовое задание. Реализованы все 40 функциональных требований и 13 пользовательских историй из `docs/prd-video-chat-room.md`.

|                |                                                                              |
| -------------- | ---------------------------------------------------------------------------- |
| **Стек**       | TypeScript (strict), React 18, socket.io 4, Express, WebRTC                  |
| **Тесты**      | 626 unit/компонентных + 40 E2E (Chromium и Firefox), покрытие **94 %** строк |
| **Требования** | Node 20 LTS (`.nvmrc`), npm 10                                               |

---

## Быстрый старт

```bash
npm ci
npm run serve        # собирает всё и поднимает на http://localhost:3001
```

Откройте `http://localhost:3001`, введите имя, нажмите «Создать комнату» — и откройте скопированную ссылку во второй вкладке.

> **Только `localhost`.** По адресу вида `http://192.168.1.10:3001` камера не заработает — см. [HTTPS и secure context](#https-и-secure-context).

## Разработка

```bash
npm run dev          # Vite :5173 (клиент) + tsx watch :3001 (сервер)
```

Vite проксирует `/socket.io` на `:3001` с `ws: true`, поэтому dev-конфигурация повторяет прод: **один origin, никакого CORS**. Без `ws: true` WebSocket-апгрейд молча не проходит — это отдельно закомментировано в `client/vite.config.ts`.

### HTTPS и secure context

`getUserMedia` и `RTCPeerConnection` доступны **только в secure context**. Единственное исключение — `localhost`. Практическое следствие:

| Адрес                       | Камера | Почему                                                              |
| --------------------------- | ------ | ------------------------------------------------------------------- |
| `http://localhost:5173`     | ✅     | localhost — исключение в спецификации                               |
| `http://192.168.1.10:5173`  | ❌     | не secure context; браузер даже не покажет `navigator.mediaDevices` |
| `https://192.168.1.10:5173` | ✅     | нужен доверенный сертификат                                         |

Приложение это распознаёт и показывает объяснение вместо белого экрана (ФТ-36), но работать по HTTP вне localhost не будет. Для прогона между машинами в одной сети:

```bash
mkcert -install
mkcert -key-file client/certs/key.pem -cert-file client/certs/cert.pem \
       localhost 127.0.0.1 ::1 192.168.1.10      # ваш LAN-IP

VITE_DEV_HOST=0.0.0.0 npm run dev                # Vite подхватит сертификат сам
```

Сертификаты в репозиторий не попадают (`.gitignore`).

## Прод-подобный запуск

```bash
npm run serve                 # сборка + node server/dist/index.js
docker compose up --build     # то же в одном контейнере
```

Один контейнер: Node раздаёт собранную статику клиента и обслуживает socket.io. В проде перед ним стоит nginx с TLS — конфигурация в [`deploy/nginx/video-chat.conf`](deploy/nginx/video-chat.conf), процедуры деплоя и rollback в [`docs/deploy-video-chat-room.md`](docs/deploy-video-chat-room.md).

Перед развёртыванием стоит проверить сетевые предусловия:

```bash
node scripts/check-network.mjs   # исходящий UDP до STUN — без него нет звонков между сетями
```

| Команда                           | Что делает                                                      |
| --------------------------------- | --------------------------------------------------------------- |
| `npm run dev`                     | клиент и сервер в режиме разработки                             |
| `npm run build`                   | сборка `shared` → `client` → `server`                           |
| `npm start`                       | запуск собранного сервера                                       |

| `npm run test:coverage`           | то же с покрытием и порогом 75 %                                |
| `npm run test:e2e`                | 40 E2E (Playwright: Chromium + Firefox, настоящий WebRTC)       |
| **`npm run verify`**              | **typecheck + lint + формат + тесты + сборка — одной командой** |
| `npm run lint` / `npm run format` | ESLint / Prettier                                               |

`npm run verify` — то, что должно быть зелёным перед любым коммитом. E2E в него не входят намеренно: они требуют загруженных браузеров и в десять раз медленнее.

## Тестирование

| Уровень          | Что покрывает                                                                                               |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| **Unit**         | `RoomStore`, валидация, антифлуд, reducer, `PeerManager` на моке `RTCPeerConnection`, политика автозапуска  |
| **Integration**  | весь контракт socket.io против **настоящего** сервера                                                       |
| **Компонентные** | RTL + jsdom: ввод имени, чат с автопрокруткой, плитка участника, экраны ошибок в связке с машиной состояний |
| **E2E**          | Playwright с фейковыми камерой и микрофоном: 13 сценариев из TDD §11.4 в двух браузерах                     |
| **Стражи**       | ESLint-правила, запрещающие конструкции, нарушающие требования (см. ниже)                                   |

Два примера тестов, которые проверяют не код, а **дизайн**:

- **E6** (`e2e/media.spec.ts`) — при выключении камеры у собеседника появляется заглушка, а `bytesReceived` по **аудио продолжает расти**. Ловит самую коварную регрессию: условный рендеринг `<video>` уносит вместе с картинкой звук пира. Проверяется именно рост, а не «больше нуля»: у мёртвого соединения счётчик просто стоит.
- **Стражи ESLint** — `react/no-danger` (ФТ-39), запрет `localStorage`/`sessionStorage`/`document.cookie` (PRD §5: состояние не сохраняется), запрет `pc.removeTrack` (даёт 6 SDP-обменов на клик по камере вместо нуля). Правило без объяснения рано или поздно отключают, поэтому у каждого в конфиге указана ссылка на требование.

Чек-лист ручных проверок — того, что физически нельзя автоматизировать (аппаратный индикатор камеры, отключение USB-камеры, эхо на четырёх микрофонах, замеры в LAN): [`docs/manual-verification-video-chat-room.md`](docs/manual-verification-video-chat-room.md).

## Переменные окружения

Все дефолты объявлены в `server/src/config.ts` и `client/src/config.ts`; ни один другой модуль не читает окружение напрямую.

### Сервер (рантайм)

| Переменная                                  | Дефолт                       | Назначение                                                      |
| ------------------------------------------- | ---------------------------- | --------------------------------------------------------------- |
| `PORT` / `HOST`                             | `3001` / `0.0.0.0`           | параметры процесса                                              |
| `LOG_LEVEL`                                 | `info`                       | уровень pino                                                    |
| `STATIC_DIR`                                | рядом со сборкой             | каталог собранного клиента                                      |
| `MAX_PARTICIPANTS`                          | `4`                          | лимит участников комнаты                                        |
| `MAX_MESSAGES`                              | `200`                        | глубина истории чата                                            |
| `MAX_NAME_LEN` / `MAX_MESSAGE_LEN`          | `30` / `500`                 | лимиты валидации                                                |
| `CHAT_RATE_BURST` / `CHAT_RATE_REFILL`      | `5` / `1`                    | антифлуд чата (не рвёт сокет)                                   |
| `SIGNAL_RATE_MAX` / `SIGNAL_RATE_WINDOW_MS` | `1000` / `10000`             | лимит сигналинга (рвёт сокет)                                   |
| `PING_INTERVAL` / `PING_TIMEOUT`            | `10000` / `5000`             | скорость обнаружения обрыва                                     |
| `MAX_HTTP_BUFFER_SIZE`                      | `100000`                     | потолок payload'а socket.io                                     |
| `SHUTDOWN_NOTICE` / `SHUTDOWN_GRACE_MS`     | `true` / `2000`              | сообщение и пауза при graceful shutdown                         |
| `HEALTH_INTERNAL_ONLY` / `HEALTH_ALLOWLIST` | `true` / приватные диапазоны | доступность `/health`                                           |
| `CORS_ORIGIN`                               | dev-адреса Vite              | список origin'ов                                                |
| `TRUST_PROXY`                               | `loopback`                   | кому доверять `X-Forwarded-For`                                 |
| `NODE_ENV`                                  | —                            | `production` в контейнере; влияет на подробность ошибок Express |

### Клиент (этап сборки)

| Переменная                                   | Дефолт                | Назначение                                       |
| -------------------------------------------- | --------------------- | ------------------------------------------------ |
| `VITE_ICE_SERVERS`                           | публичный STUN Google | список ICE-серверов (список URL или JSON)        |
| `VITE_MAX_VIDEO_BITRATE`                     | выключен              | потолок исходящего видео, бит/с                  |
| `VITE_SOCKET_URL`                            | тот же origin         | адрес сигналинга                                 |
| `VITE_SOCKET_TIMEOUT_MS`                     | `8000`                | таймаут ack при входе                            |
| `VITE_ICE_RESTART_ATTEMPTS`                  | `1`                   | попыток `restartIce()` на соединение             |
| `VITE_ICE_CANDIDATE_POOL_SIZE`               | `2`                   | предсбор ICE-кандидатов                          |
| `VITE_MAX_PARTICIPANTS`                      | `4`                   | должен совпадать с серверным                     |
| `VITE_MAX_NAME_LEN` / `VITE_MAX_MESSAGE_LEN` | `30` / `500`          | лимиты полей; должны совпадать с серверными      |
| `VITE_ROOM_ID_LENGTH`                        | `12`                  | длина `nanoid` для идентификатора комнаты        |
| `VITE_AUTOSCROLL_THRESHOLD_PX`               | `50`                  | порог «пользователь у нижней границы чата»       |
| `VITE_SHOW_CONNECTION_STATE`                 | `true`                | показывать плашку состояния соединения на плитке |

`SIGNAL_RATE_MAX` стоит `1000`, а не «сколько-нибудь»: Firefox присылает ~99 ICE-кандидатов на одно соединение против 8 у Chromium, и прежние 100 событий отключали легитимных пользователей Firefox через секунду после входа.

## Архитектура

```
Браузер ──WSS──► nginx (TLS) ──► Node: express (статика) + socket.io (сигналинг)
   │                                        состояние комнат в RAM, ОДИН инстанс
   └──────────── DTLS-SRTP, P2P mesh ────────────► Браузер
```

Клиент разделён на слои, **не знающие друг о друге**: `LocalMedia` (дорожки, ничего не знает о WebRTC) → `PeerManager` (mesh, ничего не знает о socket.io) → `roomConnection` (сигналинг, ничего не знает о `RTCPeerConnection`). Связываются они только в `roomSession`. Изоляция проверяется тестами, которые ищут запрещённые ссылки в исходниках, — иначе слои срастаются за один рефакторинг.

### Решения, которые видно только в коде

| Решение                                                               | Почему так, а не иначе                                                                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<video>` смонтирован **всегда**, заглушка — оверлей поверх           | `{hasVideo && <video/>}` при выключении камеры собеседника убивает **его звук**. Проверяется и компонентным тестом (тот же узел DOM), и E2E (аудиотрафик продолжает расти)           |
| Камера выключается `track.stop()`, микрофон — `track.enabled = false` | у камеры обязан гаснуть аппаратный индикатор (ФТ-19); остановленную аудиодорожку пришлось бы получать заново и ренегоциировать                                                       |
| `sender.replaceTrack(null)`, а не `pc.removeTrack()`                  | второе вызывает ренегоциацию на каждый клик по тумблеру. Запрещено ESLint-правилом                                                                                                   |
| Трансиверы создаются заранее, в фиксированном порядке                 | иначе SDP невалиден, когда у участника нет ни камеры, ни микрофона                                                                                                                   |
| Perfect negotiation, роль по `selfId > peerId`                        | одновременные офферы (glare) иначе кладут соединение                                                                                                                                 |
| Оффер отправляет тот, кто **уже в комнате**                           | без этого правила на каждую пару приходится два оффера                                                                                                                               |
| Состояние устройств берётся из события `media:state`, не из WebRTC    | `replaceTrack(null)` не удаляет дорожку у получателя — она замирает на последнем кадре, и собеседник видит «зависшее лицо» вместо заглушки                                           |
| Потоки и соединения живут в `useRef`, а не в состоянии React          | иначе каждый ICE-кандидат перерисовывает видеосетку                                                                                                                                  |
| Раскладка сетки выбирается **числом участников**                      | `auto-fit` при трёх участниках даёт «две плитки и одну растянутую», а требуется 2×2                                                                                                  |
| Имя передаётся в памяти модуля                                        | в URL ему не место (ссылкой делятся), web storage запрещён требованиями, а состояние навигации react-router переживает F5 и нарушило бы «после перезагрузки имя спрашивается заново» |

Полное описание — [`docs/design-video-chat-room.md`](docs/design-video-chat-room.md) (TDD, 2.0).

## Известные ограничения

Это осознанные границы решения, а не недоделки. Каждая зафиксирована в TDD §13 с оценкой риска.

| Ограничение                                | Следствие для пользователя                                                                                                                                                                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Нет TURN**                               | пара за симметричным NAT не соединится: на плитке появится «Нет соединения с участником», остальная комната продолжит работать. В корпоративной сети с закрытым UDP звонки между сетями не заработают вовсе — проверяется `scripts/check-network.mjs` |
| **Лимит 4 участника**                      | mesh даёт `n×(n-1)` потоков: на пятом участнике заканчивается и CPU, и восходящий канал. Больше — только через SFU, что меняет архитектуру целиком                                                                                                    |
| **Один stateful инстанс**                  | комнаты живут в RAM: **любой рестарт прерывает все звонки**, горизонтально сервер не масштабируется. Перед рестартом стоит посмотреть `/health`                                                                                                       |
| **История чата не сохраняется**            | выход последнего участника уничтожает переписку (это требование, а не побочный эффект)                                                                                                                                                                |
| **Перезагрузка страницы = новый участник** | имя спрашивается заново, история не восстанавливается                                                                                                                                                                                                 |
| **Safari вне поддержки**                   | целевые браузеры — Chrome, Firefox, Edge 100+. Safari требует отдельной работы с автозапуском и кодеками                                                                                                                                              |
| **Нет авторизации**                        | кто угодно с ссылкой войдёт в комнату; занятие всех четырёх слотов ботом возможно. Прямое следствие требования «вход без регистрации»                                                                                                                 |
| **Эхо без наушников**                      | четыре живых микрофона в одном помещении дают акустическую обратную связь — физика, а не дефект                                                                                                                                                       |
| **Аппаратные проверки не выполнены**       | индикатор камеры, отключение USB-камеры, замеры задержки в LAN и CPU на четырёх участниках требуют железа: список в чек-листе ручной верификации                                                                                                      |
| **`npm audit`: 11 high**                   | все — в dev-зависимостях (ESLint, vitest требуют мажорных апгрейдов). В рантайм-образ не попадают                                                                                                                                                     |
